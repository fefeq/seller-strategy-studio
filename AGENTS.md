- Onboarding reading guidance stays in a local presentation module and reuses existing finding handlers; explanatory copy must not imply that discards recalculate an already-generated proposal.
- Strict TS extras (exactOptionalPropertyTypes, noUncheckedIndexedAccess, etc.) are off: Supabase row/form code was too noisy.
- Data access goes through the browser client with RLS; only AI calls run in server functions (src/lib/ai.functions.ts).
- Multitenant: every tenant table has org_id defaulting to public.current_org() (profiles.current_org_id); RLS filters to the current org + membership, so client queries never pass org_id except in upsert conflict targets.
- Roles are per organization in org_members (user_roles is deprecated); only an org's owner may delete, manage members and invites.
- Superadmins live in platform_admins (rows only via migration/SQL); triggers make them Owner of every company, existing and new, and block removing or demoting them, so RLS and role checks need no special case.
- New orgs are created via the create_organization RPC, which also seeds default segments, integrations, positioning and docs.
- Session check (src/lib/session-check.ts, shared by the /_authenticated guard, /auth and meQuery): one GET /auth/v1/user per token with three answers, valid / none / unverified (checkSession in src/lib/session.ts). Only none (no session, 401/403) goes to /auth; unverified (network, 5xx, 429, error without status) is never saved, never signs out and shows «No he podido comprobar tu sesión» with Reintentar (src/components/session-unverified.tsx, no automatic retries); /auth follows any session event only through validatedUser() (NK-0112/NK-0113). Nothing outside session-check.ts calls auth.getUser( (source guard); lastValidatedUserId() feeds handleAuthEvent, whose «other user» rule also uses it, and dropUserCache clears mutations too; meQuery rejects, never caches null, when the session changes mid-load (NK-0110/NK-0111/NK-0115).
- Money uses the org currency via useCurrency(); never hardcode symbols; currency change relabels, never converts.
- Design system lives in src/styles.css (tokens, typography utilities, base rules: single-column grids use minmax(0,1fr), grid children and horizontal scrollers contain their content so pages never scroll sideways); shadcn primitives in src/components/ui are restyled to match, so screens keep semantic classes and never hardcode colors. Fonts come from @fontsource packages. Dark theme = .dark on <html>, chosen with ThemeToggle (src/components/theme-toggle.tsx: saved in localStorage "nokko-theme", else system preference; THEME_BOOT inline script in __root avoids a flash). Brand marks in src/components/brand.tsx keep the design-system geometry; only their colors follow tokens. Navigation lives in src/lib/nav.ts (tested): a short daily list plus collapsible groups; global search is the ⌘K command palette (src/components/command-palette.tsx).
- src/lib/ has its own AGENTS.md (domain modules, agent, MCP, metrics); read it before changing files there.
- App shell (src/routes/_authenticated/route.tsx): mobile top bar with ☰/✕ toggle and a left drawer under it (closes on navigation, tap outside, Esc or swipe left), plus a bottom bar (Inicio, Sugerencias, Leads, Pipeline, Agente) below md; the floating agent button is desktop-only. From md the sidebar can be collapsed to a rail (button or ⌘/Ctrl+B, remembered in localStorage). Pages keep pb-28 so content clears the bottom bar; sticky bottom bars sit at bottom-[calc(3.75rem+env(safe-area-inset-bottom))] on mobile. PWA manifest and icons live in public/.
- .env is generated and committed by Lovable Cloud and holds only public values (Supabase URL, project id and the sb_publishable_ key, which ships in the browser bundle anyway; RLS protects the data). Keep it in the repo (Lovable builds from it). Never add secret keys (service_role, sb_secret_, API tokens) to it or to any VITE_ variable: secrets go in Lovable Cloud secrets and are read only in server functions.
- User-facing errors go through errorText() (src/lib/errors.ts, tested): Postgres/PostgREST/auth/network errors → Spanish «qué pasó + qué hacer»; our own Spanish messages pass through. Never toast a raw error.message. Forms that copy a server record merge background refreshes with mergeServerEdits (src/lib/merge-edits.ts) so unsaved edits survive. MCP tool titles live in TITLES (src/lib/mcp/tools/agent-tools.ts) and mirrored in .lovable/mcp/manifest.json.
- Screen headlines (Inicio, Métricas, Pipeline, Leads, Cuentas, Sugerencias) are conclusions computed by pure functions in src/lib/headlines.ts (tested) from data the screen already loads; the section name goes in the eyebrow and the fallback is the section name, never an invented number. Glossary: features in Spanish (Planificador de reuniones, Preparación de llamada, Clínica de casos, Investigación de stakeholders, Brief GTM, Modelos de venta); roles and industry acronyms stay in English.
- Fields that name an existing record (company/account, person, partner, product) use EntityCombobox (src/components/entity-combobox.tsx) and duplicate rules in src/lib/match.ts (tested): link by id, warn before creating a near-duplicate, never merge.
- Big screens keep only route config and layout in the route file; each tab or panel is its own module under src/components/<screen>/ (strategy, account, setup, orchestrator), so files stay reviewable.
- No `as any`: use the generated types (Tables/TablesUpdate), `as unknown as Json` for jsonb writes, and jsonObject/actionTool (src/lib/json.ts, tested) to read jsonb; a casting gap is a narrow typed cast with a reason.
- Confirmations and one-line text prompts use askConfirm/askText (src/components/confirm-dialog.tsx, host mounted in __root), never window.confirm/prompt, so they follow the design system.
- Main screens (Inicio, Cuentas, Pipeline, Leads) read queryOptions from src/hooks/screen-queries.ts (plus meQuery/leadsQuery); their route loaders prepare that cache and the router preloads on intent, so screens open filled.
- GTM diagnosis (archetype + stage filter) is a pure rule in src/lib/gtm-diagnosis.ts (tested); onboarding stores it per user in onboarding_sessions.
- Onboarding (/onboarding): the reading runs as the `onboarding_read` background job (src/lib/onboarding.server.ts) writing findings/proposal to onboarding_sessions; block rules are pure in src/lib/onboarding.ts (tested) and approval reuses applySetupItems/undoSetupItems, so the wizard and Configuración save the same way. The AI setup prompt lives once in src/lib/setup-extract.server.ts. «Onboarding terminado» is defined once per person as `onboardingDone` (step "roadmap"; `completed_at` only means the card is hidden), the diagnosis step never needs a proposal (`stepReachable`, «Hacer solo el diagnóstico»), and the agent reads the company state with `get_onboarding_status` (`companyOnboardingStatus`: no proposal, findings, sources or ticket).
- Card decks (Sugerencias, Inicio) use SwipeDeck (src/components/swipe-deck.tsx, motion) with gesture rules in src/lib/swipe.ts (tested); decisions commit only after the undo window, so a swipe is always reversible.
- RevOps analysis (reconciled funnel, lost, cohorts, weekly trend) is pure in src/lib/revops.ts (tested, ported from the RevOps Dashboard engine) and shown as sections of /metrics selected by ?seccion=.
- Onboarding storage provisioning is an explicit native Storage API operation (scripts/provision-onboarding-storage.ts), never a page-load side effect or storage.buckets SQL, because the platform manages the storage schema.
- Durable autopilot step outputs use an explicit count-only projection before returning from step.run; core notes remain internal so Inngest history never persists customer titles or error text from them.
- The title/name log audit is a local AST scanner under scripts, exercised by a new guard alongside the protected legacy scanner; never bundle compiler-based audit tooling into served code.
- Email verification semantics live in a pure shared module keyed by normalized address; consumers must reuse its expiry and draft gate rather than delegate those decisions to a model.
- Contact screens batch visible email verification reads through one member-client helper scoped by organization; the shared mark reuses the pure expiry rule, so errors or changed addresses never appear verified.
- Icons (NK-0168): lucide icons render only through IconText (src/components/icon-text.tsx: 16 px buttons, 20 px nav, stroke 1.75) so every icon has visible text; one icon per concept (Trash2 delete, Eraser discard changes, Ban dismiss/disqualify, X only cancel/close, Check do, Spline Theory U, Cable connect assistants); the collapsed rail «›» is the only icon without text. Guarded by src/lib/icon-rule.test.ts.
- Custom-play execution uses server-only adapters and privileged RPC leases; reserve before external calls, atomically commit outputs and receipt, never replay an uncertain reservation, and return only counters to Inngest to prevent repeat spend and durable customer-text leakage. Measured AI USD costs and estimated provider EUR costs remain separate.
